# DailyMoodProject

하루에 한 번, 이모지 하나와 한 줄로 오늘의 감정을 남기고 달력·주간·월간으로 돌아보는 iPhone 앱입니다.

## 주요 기능

| 탭 | 내용 |
|---|---|
| 기록 | 오늘 기록 전에는 "오늘의 질문"으로 기록을 시작하고, 기록 후에는 오늘의 카드, 연속 기록, 인사이트, 감정별 기록을 보여 줍니다. 설정은 이 탭의 버튼으로 엽니다. |
| 달력 | 월 달력에 날마다 감정 이모지를 표시합니다. 날짜를 고르면 그날의 기록과 이전 기록을 볼 수 있고, 연도를 바로 고를 수 있습니다. |
| 주간 | 한 주의 감정 흐름과 요약을 보여 줍니다. 이전 주와 다음 주로 이동합니다. |
| 월간 | 감정 분포 도넛 차트, 기록한 날 수와 기록률, 최장 연속 기록, 하이라이트를 보여 줍니다. |

- **기록 시트**: 감정 8종(기쁨, 사랑, 평온, 설렘, 피곤, 불안, 슬픔, 화남) 중 하나를 고르고 한 줄(최대 40자)을 씁니다. 지난 날짜에도 기록할 수 있고, 미래 날짜는 고를 수 없습니다. 입력한 내용이 있는 채로 닫으면 버릴지 확인합니다.
- **하루 한 건**: 같은 날에는 기록을 하나만 남길 수 있습니다.
- **수정과 삭제**: 기록 상세 화면에서 합니다. 수정은 오늘 기록만 가능하고, 삭제는 확인 창을 거칩니다.
- **설정**: 화면 모드(시스템, 라이트, 다크), 매일 기록 알림과 알림 시간, 앱 버전, 모든 기록 삭제.
- **알림**: 정한 시간에 로컬 알림을 보냅니다. 오늘 이미 기록했으면 오늘 알림은 건너뜁니다.

## 기술 스택

| 항목 | 내용 |
|---|---|
| 언어 | Swift |
| UI | SwiftUI |
| 기록 저장 | SwiftData (`MoodEntry`) |
| 간단한 설정 | `@AppStorage` (UserDefaults). 키 이름은 `SettingsKey`에 모읍니다. |
| 차트 | Swift Charts |
| 알림 | UserNotifications |
| 개발 환경 | Xcode 27.2 |
| 최소 OS | iOS 27.2 (프로젝트 설정 `IPHONEOS_DEPLOYMENT_TARGET` 기준) |
| 대상 기기 | iPhone 기준으로 설계했습니다. 프로젝트 설정은 iPad와 Apple Vision도 허용합니다. |


## 시작하기

1. 저장소를 받습니다.

   ```sh
   git clone https://github.com/firmsteam/DailyMoodProject.git
   ```

2. `DailyMoodProject.xcodeproj`를 Xcode로 엽니다.
3. 스킴 `DailyMoodProject`를 선택하고 시뮬레이터나 기기에서 실행합니다.

시뮬레이터의 Debug 빌드는 기록이 하나도 없을 때 샘플 기록 12건을 자동으로 넣습니다. 샘플을 새로 받으려면 앱을 지우고 다시 설치합니다. Release 빌드와 실기기 빌드에는 샘플 코드가 들어가지 않습니다.

## 프로젝트 구조

```
DailyMoodProject/
├─ App/            앱 진입점, 탭·시트 상태(AppRouter), 루트 화면, 저장소(EntryStore), 알림 동기화
├─ Features/       화면별 코드
│  ├─ Record/      기록 탭 (오늘 기록 전·후)
│  ├─ Calendar/    달력 탭
│  ├─ Week/        주간 탭
│  ├─ Month/       월간 탭
│  ├─ Detail/      기록 상세 (수정·삭제)
│  ├─ Editor/      감정 기록 시트
│  └─ Settings/    설정 시트
├─ DesignSystem/   공용 컴포넌트, 타이포그래피(EmojiText, AdaptiveStack 등), 미리보기 데이터
├─ Domain/         SwiftUI·SwiftData에 기대지 않는 규칙과 통계 계산
│  └─ Stats/       연속 기록, 기간 통계, 하이라이트, 인사이트 문구
├─ Data/           MoodEntry 모델, 스키마(SchemaV1), 설정 값, DEBUG 샘플 데이터
└─ Services/       알림 예약 (ReminderScheduling 프로토콜과 시스템 구현)
```

설계에서 눈여겨볼 점은 다음과 같습니다.

- **ViewModel 없이 `@Query` 사용**: 기록이 하루 한 건이라 양이 적어서, 화면이 SwiftData를 직접 읽습니다.
- **통계는 순수 함수**: 연속 기록, 기록률, 감정 분포는 `[EntrySnapshot]`(값 복사본)을 받아 계산합니다. 저장하지 않고 매번 계산하므로 수정·삭제 때 값이 어긋나지 않습니다.
- **탭마다 `NavigationStack`**: 탭을 옮겨도 쌓인 화면과 스크롤 위치가 유지됩니다.
- **시트는 최상위에서 하나만**: `AppRouter`가 기록 시트와 설정 시트를 관리합니다.
- **알림은 날짜별로 예약**: 반복 알림은 "오늘 기록했으면 보내지 않기"를 지정할 수 없습니다. 그래서 앞으로 14일 치를 하나씩 예약하고, 상태가 바뀔 때마다 다시 예약합니다.

## 접근성과 동적 글꼴

시스템 글자 크기와 큰 글자(접근성 크기)에서도 화면이 무너지지 않도록 다음 원칙을 지킵니다.

- 글자에는 텍스트 스타일(`.font(.body)` 등)만 쓰고 고정 크기를 쓰지 않습니다. 이모지는 `@ScaledMetric` 기반의 `EmojiText`로 키웁니다.
- 글자가 들어가는 곳에는 고정 높이 대신 `minHeight`를 씁니다.
- 가로로 나란한 요소는 글자가 커지면 세로로 바꿉니다. (`AdaptiveStack`)
- 누르는 영역은 44 × 44pt 이상으로 유지합니다.
- 새 화면과 컴포넌트는 `#Preview`로 기본 크기와 `accessibility5`를 함께 확인합니다.
